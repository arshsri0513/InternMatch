# Build Log — Entry 2: 4D Check and Delegation Map

## 4D Check — Real build task
**Task:** Draft the first prototype information architecture and UI flow.

### Delegation
AI was given the task of proposing a simple Discover → Compare → Save interface. We kept the decisions about the user, the core flow, the exclusions, the data model, and what counts as done.

### Description
- **Context:** A narrow internship discovery prototype for college students.
- **Objective:** Test whether a comparison step can make opportunity selection easier.
- **Task:** Suggest a simple web flow and component structure.
- **Constraints:** One flow, no accounts, no payments, no messaging, demo data only, no credentials.
- **Output:** A browser-based prototype with discovery, comparison, and saving.
- **Success criteria:** A first-time user can complete the flow without explanation and the prototype does not violate the scope.

### Discernment
The output was judged against `PROJECT_SPEC.md`, then checked by manually running the flow and deliberately using unexpected inputs.

### Diligence
Before submission, requirements, exclusions, test results, and any factual claims must be checked by a human. Demo listings must not be presented as live verified internships.

## Untestable tasks
The team should not delegate the claim "students will use this product" to AI. That requires real user evidence. Likewise, market demand and willingness to change behaviour remain untestable without field research.

## Three review points
1. **Evidence review:** verify important research claims against original sources.
2. **User review:** compare prototype assumptions with real user behaviour.
3. **Spec review:** check the finished build against every requirement and exclusion.
